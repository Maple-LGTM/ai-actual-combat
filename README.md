dsh-plugin-toolkit.py
一款 Windows 平台 DeepSeek Harness (DSH) 插件迁移与盘符优化工具
针对 DeepSeek Harness 桌面版默认将插件、缓存、pnpm 依赖数据存储在 C 盘、占用系统盘空间的痛点，本工具基于 Python 实现自动化迁移方案。通过 NTFS Junction 符号链接 + robocopy 可靠文件同步 实现零感知数据迁移，彻底将 DSH 插件运行数据从 C 盘迁移至 D 盘，同时兼容 pnpm store 运行报错修复逻辑，兼顾迁移稳定性、完整性与程序原生运行体验。
适合 Windows 平台 DSH 桌面版用户解决 C 盘爆满、系统盘冗余缓存过多问题，全程自动化执行，无需手动修改配置、复制文件。
📌 项目核心背景
DeepSeek Harness 桌面版 Windows 版本存在固定存储逻辑：所有插件安装目录、插件运行数据、pnpm 依赖缓存均默认写入系统 C 盘用户目录。长期使用会产生大量冗余文件，导致系统盘占用过高、电脑卡顿，且官方未提供自定义存储路径的配置选项。
常规手动剪切粘贴、软链接方式易出现文件丢失、程序启动报错、pnpm 依赖失效等问题。本工具针对性解决以上痛点，提供一套稳定、完整的自动化迁移方案。
✨ 核心功能
- 全自动盘符迁移：自动定位 DSH 桌面版 C 盘插件根目录与数据目录，一键迁移至 D 盘专属目录，无需人工定位路径
- 可靠文件同步机制：调用 Windows 原生 robocopy 命令进行文件复制，支持大文件、隐藏文件、权限文件完整同步，规避 Python 原生文件库的复制丢失问题
- NTFS Junction 链接映射：迁移完成后自动创建 Junction 硬链接，让 DSH 程序继续读取原 C 盘路径，实现程序零感知运行
- pnpm store 报错修复：内置专属兼容逻辑，解决迁移后 pnpm 依赖路径失效、缓存找不到、插件启动失败等经典问题
- 安全迁移机制：执行前自动校验目录状态、避免重复迁移、防止文件覆盖损坏，全程日志可追溯
- 轻量化无依赖：纯 Python 脚本实现，无需额外安装第三方库，兼容主流 Windows10/11 系统
🛠️ 技术栈
- Python 3.x：核心脚本逻辑编写
- Windows Junction 符号链接：实现路径无缝映射
- robocopy：Windows 原生高性能文件同步工具
- 系统路径解析、目录状态校验、异常捕获处理
📖 使用教程
前置条件
1. Windows 10 / Windows 11 系统
2. 已安装 DeepSeek Harness 桌面版
3. 本地安装 Python3 环境
4. 关闭正在运行的 DeepSeek Harness 程序（避免文件占用迁移失败）
操作步骤
1. 克隆本项目到本地
        git clone https://github.com/你的用户名/dsh-plugin-toolkit.py.git
cd dsh-plugin-toolkit.py
2. 直接运行脚本
        python dsh-plugin-toolkit.py
3. 等待脚本自动执行：路径校验 → 文件全量同步 → 旧目录处理 → Junction 链接创建 → pnpm 环境修复
4. 执行完成后，重新打开 DeepSeek Harness 即可，所有插件正常运行，数据均存储至 D 盘
⚠️ 项目踩坑记录（核心技术沉淀）
本项目在开发调试过程中，解决了多个 Windows 链接与文件操作的经典坑点，也是本工具稳定性的核心保障：
1. 禁止使用 shutil.rmtree 删除 Junction 链接目录
问题现象：Python 原生 shutil.rmtree 无法识别 Windows Junction 符号链接的特性，会将链接指向的真实目标目录当作普通子目录递归删除，直接导致 D 盘已迁移的完整插件数据被清空，造成数据不可逆丢失。
解决方案：放弃 Python 原生文件删除方法，采用 Windows 原生系统命令精准识别 Junction 链接，仅删除链接本身，不穿透删除目标目录，彻底规避数据误删风险。
2. 不使用普通软链接，优先使用 Junction 链接
问题现象：普通 symlink 软链接在 Windows 权限、用户目录、程序运行权限下极易失效，DSH 启动时无法识别软链接路径，导致插件加载失败、空白报错。
解决方案：采用 NTFS 原生 Junction 链接，适配系统级目录映射，权限兼容性更强，后台程序、用户进程均可正常读取，稳定性远超普通软链接。
3. 放弃 Python 原生文件复制，采用 robocopy
问题现象：Python 原生 shutil.copy / os.copy无法完整复制隐藏文件、权限受限文件、超长路径文件，会出现部分 pnpm 缓存文件、插件配置文件丢失，导致迁移后插件启动异常。
解决方案：调用 Windows 内置 robocopy 命令，支持超长路径、隐藏文件、权限文件、大文件断点续传式同步，保证迁移前后文件100% 完整一致。
4. 迁移后 pnpm store 路径报错问题
问题现象：DSH 插件依赖 pnpm 包管理，迁移目录后，pnpm 缓存路径硬编码失效，出现 store not found、依赖解析失败、插件无法加载等问题。
解决方案：脚本内置 pnpm 路径重置、缓存校验、环境适配逻辑，自动修复路径映射问题，无需用户手动配置 pnpm 环境。
✅ 优势总结
- 安全性高：规避链接删除、文件丢失、路径失效等各类经典问题，无数据丢失风险
- 兼容性强：原生系统命令实现，不依赖第三方库，适配所有主流 Windows 版本
- 无感迁移：通过 Junction 链接保留程序原生读取逻辑，无需修改软件源码与配置
- 解决核心痛点：彻底释放 C 盘空间，根治 DSH 系统盘冗余占用问题
